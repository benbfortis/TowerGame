# Web-to-Device Deployment — Technical Specification

## Purpose

This document describes the toolchain, configuration, and commands required to take a TypeScript/Vite web application and deploy it as a native Android (or iOS) app via Capacitor. It covers only the build and deployment pipeline — not application logic.

---

## Prerequisites

### Node.js toolchain
- **Node.js** 18+ (ESM-native — `"type": "module"` in `package.json`)
- **npm** 9+

### Android
- **Android Studio** — required once to install the SDK and accept licenses
- **Java 17** (bundled with Android Studio or installed separately)
- **Android SDK** — compileSdk 34, minSdk 22, targetSdk 34
- **ADB** (`platform-tools`) on `PATH`
- A physical Android device in USB debug mode, or an emulator

### iOS (macOS only)
- **Xcode** 15+
- **CocoaPods** (`sudo gem install cocoapods`)

## Capacitor Configuration

`capacitor.config.ts` — the single source of truth for the app identity:

```ts
const config: CapacitorConfig = {
  appId:   'com.gametest01.app',
  appName: 'Game',
  webDir:  'dist',               // Vite output dir
  server: {
    androidScheme: 'https',
    // CAP_SERVER_URL env var injects a dev server URL for livereload builds
    ...(devServerUrl ? { url: devServerUrl, cleartext: true } : {}),
  },
};
```

`devServerUrl` is read from `process.env.CAP_SERVER_URL`. When absent (production), the WebView loads from the bundled `dist/` assets. When present, it loads from the remote Vite server.

## Vite Build Configuration

`vite.config.ts` — relevant to deployment:

```ts
export default defineConfig({
  build: {
    outDir:               'dist',
    target:               'es2020',
    chunkSizeWarningLimit: 2000,
    rollupOptions: {
      output: {
        manualChunks: {
          // split large deps into a separate chunk to stay under APK asset limits
          babylon: ['@babylonjs/core', '@babylonjs/gui', '@babylonjs/loaders', '@babylonjs/materials'],
        },
      },
    },
  },
  server: { port: 3000 },
});
```

The `manualChunks` entry is the key deployment concern: without it, the single bundle exceeds Android's asset file-size limit for `aaptOptions`.

## Build and Deploy Commands

### 1. Browser dev server (no device)

```bash
npm run dev
```

Runs `node scripts/dev.mjs`, which starts Vite on port 3000.

---

### 2. Production build (web only)

```bash
npm run build
```

Runs `tsc && vite build`. TypeScript is type-checked first (errors block the build), then Vite outputs `dist/`.

---

### 3. Sync web build into native project

```bash
npx cap sync
```

Copies `dist/` into `android/app/src/main/assets/public/` (and the iOS equivalent), then updates native plugin registration. This must be run after every `npm run build` before assembling the APK.

`npm run cap:sync` combines both steps: `npm run build && npx cap sync`.

---

### 4. Android — full build + install + launch

```bash
npm run cap:android:deploy
```

Runs in sequence:
1. `npm run cap:sync` — builds web + syncs into Android project
2. `cd android && gradlew.bat assembleDebug` — assembles debug APK
3. `adb install -r android\app\build\outputs\apk\debug\app-debug.apk`
4. `adb shell am start -n com.gametest01.app/com.gametest01.app.MainActivity`

Output APK path: `android/app/build/outputs/apk/debug/app-debug.apk`

To install an already-built APK without rebuilding:

```bash
npm run adb:install   # install only
npm run adb:run       # install + launch
```

---

### 5. Android — live-reload (no full rebuild per change)

```bash
npm run cap:android:livereload
```

Implemented in `scripts/cap-android-livereload.mjs`. Steps:

1. Detects LAN IP (or reads `HOST_IP` env var)
2. Sets `CAP_SERVER_URL=http://<ip>:<port>` → injects the dev server URL into `capacitor.config.ts` at runtime
3. Runs `npx cap sync android` with the env var to bake the URL into the WebView config
4. Assembles and installs the APK once via Gradle + ADB
5. Starts Vite on `0.0.0.0:<port>` — the installed APK loads from the live Vite server
6. On exit, runs `cap sync android` without `CAP_SERVER_URL` to restore production config

**Environment variable overrides:**

| Variable | Effect |
|---|---|
| `HOST_IP=192.168.x.x` | Override auto-detected LAN IP |
| `PORT=3001` | Override Vite port (default 3000) |
| `ADB_REVERSE=1` | Use USB tunnel instead of Wi-Fi (`adb reverse tcp:PORT tcp:PORT`) |

`ADB_REVERSE=1` is required on networks that isolate clients (hotel Wi-Fi, corporate Wi-Fi).

---

### 6. iOS

```bash
npm run cap:ios
```

Runs `npm run cap:sync && npx cap open ios` — syncs the build then opens Xcode. From Xcode, select a device/simulator and press Run. There is no headless deploy command; Xcode is required.

---

### 7. Release APK (unsigned, requires manual signing)

```bash
npm run cap:android:release
```

Runs `npm run cap:sync && cd android && gradlew.bat assembleRelease`. Output: `android/app/build/outputs/apk/release/app-release-unsigned.apk`. Must be signed with `apksigner` or via Android Studio before distribution.

## Data Layer

### Overview

All tuning values (speeds, sizes, durations, colours, counts, positions, damage) must live in `src/data/*.json`. TypeScript source files never hardcode these values — they import from the central store.

### Data files

| File | Owns |
|---|---|
| `src/data/player.json` | Player stats, size, model scale, flash duration, indicator geometry |
| `src/data/enemy.json` | Enemy stats, model, melee, ranged (arrowSpeed/arrowRange), knockback, pathfinding |
| `src/data/arrow.json` | Player arrow speed/range/damage, visual dimensions, hit radius padding |
| `src/data/spawner.json` | Wave spawn interval, band depth, spawn attempts, fallback positioning |
| `src/data/level.json` | Arena dimensions, wall geometry, player spawn, obstacle layout |
| `src/data/camera.json` | Camera FOV, pitch, clip planes, initial position |
| `src/data/scene.json` | Kill target, frame cap, auto-fire cooldown, fog, lighting, kill-shake |
| `src/data/ui.json` | Damage number colours, font sizes, float speed, lifetime, outline |
| `src/data/impactFlash.json` | Impact particle counts, sizes, lifetimes, colour gradients |

### Rules — follow all without exception

1. **Before writing any numeric or string literal** that represents a tuning value, check whether it belongs in an existing file above. If yes, add it there. If it belongs to a new system, create `src/data/<system>.json`.
2. **Import via the store**, not directly from JSON. The store provides HMR-patched mutable objects:
   ```ts
   import { playerData } from '../data/store';
   // playerData.speed — updates live on JSON edit, no reload
   ```
3. **No module-level `const` magic numbers.** `const SPEED = 3` is hardcoding with extra steps. Put the value in JSON and reference `data.speed` directly.
4. **When editing existing TypeScript**, grep for numeric literals and verify each one is already driven by JSON or is trivially non-tunable (e.g. `Math.PI / 2`, array indices, bit flags).
5. **When adding a JSON field**, verify it is actually read in TypeScript — unused JSON fields are as bad as hardcoded values.

### HMR data store (`src/data/store.ts`)

The store is the single import point for all JSON data. It:

- Deep-clones each JSON file into a mutable exported object (`playerData`, `enemyData`, etc.) on first load
- Registers `import.meta.hot.accept()` per file — when a JSON file changes on disk, Vite pushes the update and `store.ts` patches the mutable object **in place** using `deepReplace()`
- Exposes `onDataReload(listener)` so systems can subscribe to specific file changes without a full module reload
- Persists the mutable objects across HMR re-evaluations via `import.meta.hot.data` so object references remain stable

Consumer code reads `playerData.speed` on every frame — it sees updated values immediately after a JSON edit, with no page reload and no reference invalidation.

## Data Editor

```bash
npm run editor
```

Starts Vite on port 3000 with a separate entry point at `/editor.html`. The editor is a browser UI for editing `src/data/*.json` files directly, without touching the file system manually.

### How it works

The data editor is served by a Vite plugin (`dataEditorPlugin` in `vite.config.ts`) that adds REST endpoints under `/api/editor/`:

| Endpoint | Method | Purpose |
|---|---|---|
| `/api/editor/files` | GET | List all JSON files in `src/data/` |
| `/api/editor/file/:name` | GET | Read a single JSON file |
| `/api/editor/file/:name` | PUT | Write a single JSON file (triggers HMR) |
| `/api/editor/ping` | POST | Heartbeat from a running game client |
| `/api/editor/status` | GET | List connected game clients (browser + device) |
| `/api/editor/log` | POST | Receive a console log entry from the game |
| `/api/editor/logs/history` | GET | Poll incremental log entries (supports `?after=<id>`) |

When the editor PUTs a JSON file, Vite's file watcher detects the change and triggers the HMR accept callback in `store.ts`, which patches the live game data in place. The running game reflects the change on the next frame — no reload required.

### Game client tracking

The running game posts a heartbeat to `/api/editor/ping` every few seconds with:
- `clientId` — a stable random ID generated at game start
- `kind` — `"browser"` or `"device"` (Capacitor detection)
- `userAgent`

The editor banner uses `/api/editor/status` to show which clients are connected (browser vs. physical device). Clients not seen within 8 seconds are marked stale.

### Console streaming

The game forwards all `console.log/warn/error` calls to `/api/editor/log`. The editor polls `/api/editor/logs/history?after=<lastId>` incrementally to display a live console split by source (Browser / Device). Up to 1000 entries are buffered server-side.

### Running alongside livereload

The editor and `cap:android:livereload` can run simultaneously: the livereload APK points its WebView at the Vite dev server (port 3000), and the editor is opened in a browser tab at the same origin. Both share the same Vite instance, so JSON edits propagate to the device WebView and appear in the editor console in real time.

## Deployment Flow Summary

```
src/ (TypeScript + assets)
       │
       ▼  tsc (type-check) + vite build
     dist/
       │
       ▼  npx cap sync
android/app/src/main/assets/public/
       │
       ▼  gradlew assembleDebug
     app-debug.apk
       │
       ▼  adb install -r
     Device (WebView loads bundled dist/)

— OR for livereload —

     Device (WebView loads http://<host>:3000 live)
```
